## 概览

Go 1.27（2026-08 发布，当前 1.27.1）是**语言层面的大版本**：泛型方法正式落地（proposal #77273），`encoding/json/v2` GA，runtime 默认感知容器 CPU 配额。与 1.25→1.26（新表达式、Green Tea GC 实验）相比，1.27 对现有代码的影响面更大——尤其是 JSON 栈和容器部署行为。

| 维度 | 1.26 | 1.27 |
|------|------|------|
| 泛型方法 | ❌ 不允许 | ✅ 允许（接口方法除外） |
| json/v2 | 实验（GOEXPERIMENT=jsonv2） | ✅ GA，v1 改由 v2 实现 |
| 容器感知 GOMAXPROCS | GODEBUG 实验开关 | ✅ 默认开启 |
| goroutineleak profile | 实验 | ✅ GA（/debug/pprof/goroutineleak） |
| Green Tea GC | 实验 | 仍为实验（预测未命中） |
| macOS 最低版本 | 11 Big Sur | 13 Ventura |

## 一、语言变化

### 1.1 泛型方法（最大变更）

**Before (≤1.26)**：方法不能有类型参数，通用逻辑只能写成泛型函数并把 receiver 作参数：

```go
type Stack[T any] struct{ items []T }

// 只能这样：泛型函数 + 显式传参
func Drain[U any, T any](s *Stack[T], convert func(T) U) []U {
    out := make([]U, 0, len(s.items))
    for _, v := range s.items { out = append(out, convert(v)) }
    s.items = nil
    return out
}
strs := Drain(&s, strconv.Itoa)
```

**After (1.27)**：方法可声明自己的类型参数：

```go
func (s *Stack[T]) Drain[U any](convert func(T) U) []U {
    out := make([]U, 0, len(s.items))
    for _, v := range s.items { out = append(out, convert(v)) }
    s.items = nil
    return out
}
strs := s.Drain(strconv.Itoa) // U 从实参推导
```

**标准库首个用例**：`math/rand/v2.Rand.N[Int intType](n Int) Int`——一个方法覆盖所有整数类型的随机数生成。

**限制**：
- 接口方法仍不允许类型参数：`interface { M[T any](T) }` 非法。
- 泛型方法不满足接口（方法集匹配要求精确签名）。

详见 [LD-037-Go-1.27-Generic-Methods](../LD-037-Go-1.27-Generic-Methods.md)。

### 1.2 结构体字面量 key 泛化

```go
type Inner struct{ X int }
type Outer struct{ Inner }

// Before: 编译错误（字面量 key 只允许顶层字段名）
// After (1.27): 合法
o := Outer{Inner.X: 42}
```

### 1.3 泛型函数类型推断泛化

```go
type Op[T any] func(T, T) T
func Add[T ~int](a, b T) T { return a + b }

var f Op[int] = Add  // 1.27：赋值/转换为具名函数类型时从目标类型推断 T
```

## 二、Runtime 与 GC

### 2.1 container-aware GOMAXPROCS 默认开启

```go
// 容器中，1.26 默认：
runtime.GOMAXPROCS(0) // = 宿主机核数（如 64），与 cgroup 配额（如 2）严重不匹配

// 1.27 默认：
runtime.GOMAXPROCS(0) // = min(宿主机核数, cgroup 配额)
```

- 回退：`GODEBUG=containermaxprocs=0`
- 影响：未显式设置 GOMAXPROCS 的容器应用 P 数骤降，调度竞争减少，通常吞吐/延迟改善；但依赖"多 P"行为的并发 bug 可能被掩盖或暴露。
- 本仓库示例 `examples/go125/runtime/container_scheduling` 仍按实验口径撰写，现该行为已是默认。

### 2.2 小对象分配优化

- <80B 分配路径特化：最高 30%，整体约 1%；二进制约 +60KB。
- `GOEXPERIMENT=nosizespecializedmalloc` 可关，**1.28 移除**。

### 2.3 goroutineleak profile GA

- 1.26：`GOEXPERIMENT=goroutineleakprofile`
- 1.27：默认可用，`/debug/pprof/goroutineleak` 端点；语义 = 启动后持续阻塞且未退出的 goroutine。

### 2.4 GC：Green Tea GC 预测复盘

1.26 引入的 Green Tea GC（实验）曾预测 1.27 finalize——**未成真**。1.27 中仍需 `GOEXPERIMENT=greenteagc`，`nogreenteagc` 回退开关仍在。继续追踪 1.28。

### 2.5 移除项

- `asynctimerchan` GODEBUG 永久移除（time 通道恒无缓冲）。
- go≥1.27 模块 traceback 头部含 pprof goroutine labels（`tracebacklabels=0` 关）。

## 四、标准库

### 4.1 新包

| 包 | 说明 |
|----|------|
| `encoding/json/v2` + `jsontext` | GA；迁移指南见 [../../docs/go127-json-v2-migration.md](../../../docs/go127-json-v2-migration.md) |
| `uuid` | 顶层包：`uuid.NewV7()`、`NewV4()`、`Parse()`、`MustParse()`、`Max()`、`Nil()`；`type UUID [16]byte`，版本号 = `u[6] >> 4` |
| `crypto/mldsa` | FIPS 204 后量子签名（ML-DSA-44/65/87）；x509/tls 同步支持 |
| `simd` / `simd/archsimd` | 实验（`GOEXPERIMENT=simd`）；amd64 修订、arm64 Neon、wasm 128-bit |

### 4.2 新 API 精选

`strings/bytes.CutLast`、`url.URL.Clone`、`url.Values.Clone`、`math/big.Int.Divide`（舍入模式）、`hash/maphash.Hasher[T]`、`httptest.NewTestServer` + `testing/synctest.Sleep`、`net/http.Server.MaxHeaderValueCount`、`testing/cryptotest.SetGlobalRandom`、`crypto/tls` MLKEM1024、Unicode 17。

### 4.3 行为变化（升级前必须回归）

1. **JSON**：v1 由 v2 实现——错误文本可能不同；`,string`/`Decoder.Token` 回归已在 1.27.1 修复。
2. **HTTP**：HTTP/1 body 关闭自动 drain；HTTP/2 默认尊重 RFC 9218 客户端优先级。
3. **flate**：zip/gzip/zlib/png 输出字节可能变化（影响校验和可重现性）。
4. **net.UnixConn**：EOF 不再包 `net.OpError`。
5. **x509**：Windows/Darwin 的 `SystemCertPool` 尊重 `SSL_CERT_FILE/SSL_CERT_DIR`。
